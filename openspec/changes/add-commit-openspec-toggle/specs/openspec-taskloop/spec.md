# Spec Delta

## MODIFIED Requirements

### Requirement: Коммит после ревью выполняется плагином

Плагин SHALL выполнять коммит после ревью сам, без участия модели, инструментом из конфигурации: `git` или `but commit -b <ветка> -m` (GitButler; ветка — по требованию «Выбор ветки GitButler для коммита»). С включённой настройкой «Commit openspec files» коммит SHALL включать все изменения рабочего дерева, с выключенной — изменения под `openspec/` SHALL NOT в него попадать, и та же граница SHALL применяться к проверке «есть что коммитить». Пустое множество SHALL пропускать коммит с причиной в докладе, а сбой коммита SHALL останавливать прогон с докладом. При коммите через GitButler плагин SHALL приводить к LF окончания строк в файлах, которые войдут в коммит (список — при выключенной настройке, все изменения — при включённой), кроме файлов, чей blob в `HEAD` уже хранится в CRLF; файл без CRLF, двоичный файл и симлинк SHALL NOT переписываться, а смешанный blob файла SHALL попадать в доклад предупреждением.

#### Scenario: Коммит через git

- **WHEN** инструмент коммита равен `git`, настройка «Commit openspec files» включена и в рабочем дереве есть изменения
- **THEN** плагин добавляет все изменения и выполняет `git commit -m` с сообщением, собранным из текста пользователя и диапазона задач

#### Scenario: Коммит через GitButler

- **WHEN** инструмент коммита равен `gitbutler`, в рабочем дереве есть изменения и ветка выбрана
- **THEN** плагин выполняет `but commit -b <ветка> -m` с тем же сообщением, а для новой ветки — сначала `but branch new <имя> -A <anchor>`

#### Scenario: Изменения openspec исключены из коммита

- **WHEN** настройка «Commit openspec files» выключена и в рабочем дереве есть изменения как вне `openspec/`, так и под ним
- **THEN** коммит содержит только изменения вне `openspec/`, а изменения под `openspec/` остаются незакоммиченными в рабочем дереве

#### Scenario: Изменения openspec исключены при GitButler

- **WHEN** настройка «Commit openspec files» выключена, инструмент коммита равен `gitbutler` и ветка выбрана
- **THEN** плагин выполняет `but commit -b <ветка> -m` со списком изменённых файлов вне `openspec/`, и эти изменения оказываются в коммите, а изменения под `openspec/` — нет

#### Scenario: Окончания строк не смешиваются в коммите

- **WHEN** инструмент коммита равен `gitbutler`, изменённый файл вне `openspec/` лежит в рабочей копии с окончаниями строк CRLF, а его blob в `HEAD` — с LF
- **THEN** перед `but commit` плагин переписывает этот файл в LF, коммит получает строки без CR, и после коммита `git status` не показывает файл изменённым

#### Scenario: Файл, хранящийся в CRLF, не переписывается

- **WHEN** у изменённого файла blob в `HEAD` уже весь в CRLF
- **THEN** плагин не трогает этот файл, и коммит идёт как раньше

#### Scenario: Двоичный файл не переписывается

- **WHEN** среди файлов коммита есть двоичный файл, в первых килобайтах которого встречается NUL
- **THEN** плагин не переписывает его, даже если в нём есть байт CR

#### Scenario: При включённой настройке нормализуются все изменённые файлы

- **WHEN** настройка «Commit openspec files» включена, инструмент коммита равен `gitbutler` и в рабочем дереве несколько изменённых файлов с CRLF
- **THEN** плагин приводит к LF каждый из них до `but commit`, включая файлы под `openspec/`

#### Scenario: Для git нормализации нет

- **WHEN** инструмент коммита равен `git`
- **THEN** плагин не переписывает файлы, потому что `git add -A` нормализует их сам

#### Scenario: Несостоявшийся коммит не трогает индекс

- **WHEN** файлы уже нормализованы, а `but commit` завершился ошибкой
- **THEN** файлы остаются в LF, индекс не менялся, и прогон останавливается с докладом о сбое

#### Scenario: Смешанная история остаётся смешанной

- **WHEN** blob изменённого файла уже смешан — часть строк с CRLF, часть с LF
- **THEN** плагин нормализует изменённые строки, а доклад предупреждает, что история файла смешана и коммит её не вылечит

#### Scenario: Нечего коммитить

- **WHEN** рабочее дерево не содержит изменений
- **THEN** плагин не выполняет коммит и указывает в докладе, что коммитить было нечего

#### Scenario: Изменился только openspec

- **WHEN** настройка «Commit openspec files» выключена и все изменения рабочего дерева находятся под `openspec/`
- **THEN** плагин не выполняет коммит, доклад сообщает, что коммитить было нечего вне `openspec/`, и прогон продолжается как при пустом дереве

#### Scenario: Сбой коммита

- **WHEN** выбранный инструмент завершился ошибкой
- **THEN** плагин останавливает прогон, сообщает инструмент, код возврата и причину, и не запускает следующую задачу

### Requirement: Вкладка настроек плагина

Плагин SHALL предоставлять в Settings dsh страницу настроек рядом с General и Models. Страница SHALL показывать и сохранять включение коммита после группы, включение изменений `openspec/` в коммит, инструмент коммита, включение код-ревью после группы, включение паузы после каждой группы задач, включение сжатия внутри задачи, статичную секцию протокола, политику при исчерпании попыток сжатия, число попыток сжатия, первую паузу сжатия и множитель паузы. Изменение SHALL применяться следующим прогоном без перезапуска Harness.

#### Scenario: Страница присутствует

- **WHEN** пользователь открывает Settings dsh
- **THEN** в списке страниц есть OpenSpec Taskloop, и она показывает текущие значения всех одиннадцати настроек

#### Scenario: Порядок строк

- **WHEN** пользователь открывает страницу OpenSpec Taskloop
- **THEN** строка «Commit openspec files» стоит сразу после «Commit after each task group», а строка «Protocol section» — сразу после «Compact inside a task»

#### Scenario: Смена инструмента коммита

- **WHEN** пользователь выбирает на странице GitButler
- **THEN** значение сохраняется в конфигурации профиля, и следующий коммит выполняется через `but commit`

#### Scenario: Изменения openspec выключены из коммита

- **WHEN** пользователь снимает переключатель «Commit openspec files»
- **THEN** значение сохраняется в конфигурации профиля, и следующий коммит группы не включает изменения под `openspec/`

#### Scenario: Изменение применяется без перезапуска

- **WHEN** настройка изменена на странице
- **THEN** следующий прогон использует новое значение без перезапуска Harness

#### Scenario: Пауза после группы

- **WHEN** пользователь включает на странице паузу после каждой группы задач
- **THEN** следующий прогон заканчивается на границе первой завершённой группы, не открывая сессию следующей

#### Scenario: Политика при неудачном сжатии

- **WHEN** пользователь выбирает на странице политику «продолжать»
- **THEN** следующий исчерпанный бюджет сжатия не останавливает прогон: задача отправляется, а в доклад добавляется предупреждение

#### Scenario: Сжатие внутри задачи включено

- **WHEN** пользователь включает сжатие внутри задачи
- **THEN** следующий прогон запрашивает сжатие по давлению на границах шагов задач

#### Scenario: Секция протокола включена

- **WHEN** пользователь включает секцию протокола
- **THEN** следующий прогон регистрирует статичную секцию на агентах, которых ведёт

#### Scenario: Число попыток сжатия изменено

- **WHEN** пользователь вводит в поле числа попыток значение 5 и подтверждает ввод
- **THEN** значение сохраняется в конфигурации профиля, и следующий прогон делает не более пяти вызовов сжатия на одном переходе

#### Scenario: Первая пауза изменена

- **WHEN** пользователь вводит в поле первой паузы 20 секунд и подтверждает ввод
- **THEN** значение сохраняется в конфигурации профиля, и следующий переход ждёт 20 секунд перед первым повтором

#### Scenario: Множитель паузы изменён

- **WHEN** пользователь вводит в поле множителя значение 1
- **THEN** значение сохраняется в конфигурации профиля, и следующий прогон ждёт одинаковую паузу перед каждым повтором

#### Scenario: Расписание показано до прогона

- **WHEN** пользователь меняет любое из трёх числовых полей ретраев
- **THEN** страница показывает вычисленную последовательность пауз для текущих значений и худшее суммарное ожидание

#### Scenario: Недопустимое значение отклоняется

- **WHEN** пользователь вводит в поле числа попыток 0 или в поле первой паузы отрицательное число
- **THEN** запись отклоняется, страница показывает сохранённое значение и сообщение об отказе, и прогон на этой настройке не запускается
