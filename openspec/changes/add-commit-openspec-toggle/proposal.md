# Proposal

## Why

Прогон `/taskloop` коммитит рабочее дерево целиком, поэтому в каждый коммит группы попадает и служебная часть OpenSpec — галочки в `tasks.md`, правки `spec.md`, `design.md`, `archive/`. История кода смешивается с историей планирования: диффа группы не видно без фильтра, а откат коммита откатывает и отметки о выполненных задачах. Пользователю нужен способ держать эти две истории раздельно, не отказываясь от автоматического коммита.

Вторая, небольшая правка — порядок строк на странице настроек: `Protocol section` стоит последней, в отрыве от `Compact inside a task`, хотя README прямо связывает их как пару, которую включают вместе.

## What Changes

- Новая булева настройка `commit.openspec` (подпись `Commit openspec files`, по умолчанию `true`): включена — коммит группы содержит всё рабочее дерево, как сегодня; выключена — изменения файлов под `openspec/` в автоматический коммит не попадают и остаются незакоммиченными.
- Ворота «есть ли что коммитить» проверяют то же множество изменений, что попадёт в коммит: при выключенной настройке группа, где изменился только `openspec/`, даёт «коммитить было нечего» с уточнением «вне `openspec/`», а не сбой инструмента.
- Исключение работает для обоих инструментов коммита: `git` получает pathspec-исключение, GitButler — явный список изменённых файлов вне `openspec/` позиционными `CHANGES` (у `but commit` нет флага исключения).
- Новая строка на странице настроек — вторая по счёту, сразу после `Commit after each task group`; `Protocol section` переезжает из конца списка вплотную к `Compact inside a task`.
- Страница описывает одиннадцать настроек вместо десяти; README и спецификация приводятся в соответствие.

Настройка по умолчанию включена, поэтому поведение существующих профилей не меняется: без вмешательства пользователя коммит остаётся прежним — всё рабочее дерево.

Разрывов совместимости нет: поле добавлено в конфигурацию со значением по умолчанию, профиль без него загружается и работает как раньше.

## Capabilities

### New Capabilities

Нет: поведение принадлежит существующей возможности плагина.

### Modified Capabilities

- `openspec-taskloop`: требование «Коммит после ревью выполняется плагином» — коммит перестаёт быть безусловно «всеми изменениями рабочего дерева»: при выключенной настройке множество изменений сужается до всего, что вне `openspec/`, а проверка «нечего коммитить» применяется к тому же суженному множеству.
- `openspec-taskloop`: требование «Вкладка настроек плагина» — страница показывает и сохраняет одиннадцать настроек вместо десяти, новая строка `Commit openspec files` стоит второй, а `Protocol section` — сразу после `Compact inside a task`.

## Impact

- `lib/commit.js` — разбор `git status --porcelain` (сейчас только проверка на пустоту), фильтрация путей, pathspec для `git`, позиционные `CHANGES` для `but`, новый вид исхода «пусто из-за фильтра».
- `lib/config.js` — поле `commit.openspec` (volatile, по умолчанию `true`) и его описание в схеме.
- `lib/control.js` — чтение настройки в момент коммита и передача её в `runCommit`; фраза доклада для отфильтрованного «нечего коммитить».
- `lib/client.js` — новая строка настроек и новый порядок строк.
- `openspec/specs/openspec-taskloop/spec.md` — дельты двух требований.
- `README.md` — таблица настроек, раздел конфигурации, абзац о коммите.
- `test/` — `commit`, `config`, `client`, `control`, плюс блок `config-defaults` в `design.md`, из которого `test/config.test.mjs` читает задокументированные значения по умолчанию.
