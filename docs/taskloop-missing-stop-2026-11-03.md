# Разбор: taskloop остановился с «11.4 no longer listed by openspec»

**Дата разбора:** 2026-11-03
**Сессия:** `session-0b8f1713-d8d1-4d6c-8e03-e60b562efb4a`
**Рабочая директория:** `/home/ext.asfadeev/work/ecomm-shopping-logistics`
**Change:** `chktl-2304-delivery-cost-correction`

## 1. Симптом

В сессии `session-0b8f1713` был вызван `/taskloop`. Прогон стартовал,
отправил задачи **11.1, 11.2, 11.3, 11.4** (по одной за ход), а затем
остановился с ошибкой:

```
taskloop: OpenSpec root: /home/ext.asfadeev/work/ecomm-shopping-logistics.
Change "chktl-2304-delivery-cost-correction" (56/59 tasks done).
sent tasks 11.1, 11.2, 11.3 and 11.4, but 11.4 is no longer listed by openspec;
the run stopped and no further task was sent.
```

Пользователь передал сообщение в обрезанном виде: `Change "chktl-2304-deliver ...`,
что соответствует полному имени change `chktl-2304-delivery-cost-correction`.

## 2. Как это НЕ выглядит

Это **не** ошибка «изменение не найдено». Если бы имя change не совпало, плагин
выдал бы `no change named "<имя>". Available changes: ...` (из `selectChange`,
`lib/changes.js`). Здесь имя change распознано верно — проблема на другом уровне,
в верификации отправленной задачи.

## 3. Механика плагина, разобранная по коду

Ключевые файлы:

- `lib/tasks.js` — парсинг `openspec instructions apply --json`.
- `lib/loop.js` — цикл прогона и стоп-условия.
- `lib/control.js` — рендер результата в сообщение.

### 3.1 Идентификация задачи

После отправки задачи плагин запоминает её «идентичность» по трём полям:

- `sourcePath` — файл с чекбоксом (`.../tasks.md`);
- `line` — 1-based строка чекбокса в этом файле;
- `description` — **дословный текст** задачи после чекбокса.

`findListedTask` (`lib/tasks.js`, строки ~206–211) ищет задачу по строгому
совпадению всех трёх полей:

```js
export function findListedTask(instructions, task) {
  return instructions.tasks.find((candidate) =>
    candidate.sourcePath === task.sourcePath
    && candidate.line === task.line
    && candidate.description === task.description)
}
```

### 3.2 Стоп-условие «missing»

После завершения хода агента плагин заново читает tasks.md и ищет отправленную
задачу по той же тройке полей (`lib/loop.js`, ~461–465):

```js
if (previous !== undefined) {
  const refreshed = findListedTask(instructions, previous)
  if (refreshed === undefined) {
    return settleNow(LOOP_END.missing)
  }
  ...
}
```

Если задача не найдена — `LOOP_END.missing` (`lib/loop.js`, ~114), что и порождает
сообщение «... but 11.4 is no longer listed by openspec; the run stopped ...»
(`lib/control.js`, ~919–925). Отдельный случай «не отмечена галочка» — это другой
код (`LOOP_END.unmarked`).

Вывод из кода: **задача считается «пропавшей», если изменился хотя бы один из
трёх опознавательных сигналов** — чаще всего строка сдвинулась (`line`) или
изменился текст (`description`).

## 4. Что реально произошло (по транскрипту сессии)

Транскрипт: `~/.dsh/sessions/--home-ext.asfadeev-work-ecomm-shopping-logistics--/session-0b8f1713-.../session.v4.jsonl.zstd`

Хронология по блокам задач 11.x:

1. **Turn 4** (explore / планирование). В tasks.md ранее был только раздел
   «11. Открытый вопрос (не в скоупе)». В режиме explore агент **заново добавил**
   раздел «11. Гарантия отправки события корректировки…» и задачи 11.1–11.7
   (правка через `edit`). До этой правки рабочих задач 11.1–11.7 не существовало.

2. **Turn 5** — реализована и отмечена `[x]` задача 11.1.
3. **Turn 6** — реализована и отмечена `[x]` задача 11.2.
4. **Turn 7** — реализована и отмечена `[x]` задача 11.3.
5. **Turn 8** — задача 11.4. Здесь произошёл сбой:
   - агент выполнил тест, он прошёл (16 тестов);
   - **step 26**: агент отметил 11.4 как `[x]` и **дописал примечание в текст строки**,
     где, по ходу, появилась опечатка «расрешiver»;
   - **step 27**: первая попытка исправить опечатку — `edit` выпал с
     «Error: old_string and new_string must diff»;
   - **step 28**: повторный `edit` успешно заменил «расрешiver» → «резолвер».

В результате текст строки tasks.md для задачи 11.4 был изменён относительно того,
что taskloop запомнил при отправке (описание переписано + исправлена опечатка).
`findListedTask` не нашёл задачу по дословному `description` → `LOOP_END.missing`
→ прогон остановлен.

### Итоговая первопричина

> **Агент редактировал текст задачи 11.4 в tasks.md во время её выполнения
> (отметка `[x]` + дописанное примечание + исправление опечатки). Taskloop
> сверяет отправленную задачу по неизменному тексту `description`, поэтому строка
> перестала совпадать — плагин решил, что задача «исчезла», и остановил прогон.**

Это корректное защитное поведение плагина («файл изменился под прогоном»), а не
поломка. Ориентир в комментарии `findListedTask`: задача могла быть удалена или
переписана, и это должно быть стоп-условием.

## 5. Текущее состояние

После разбора состояние консистентно:

- в tasks.md: 11.1–11.4 отмечены `[x]`; открыты 11.5, 11.6, 11.7;
- `openspec list --json`: `chktl-2304-delivery-cost-correction 56 / 59 in-progress`;
- код задач 11.x сохранён в рабочем дереве (изменения не закоммичены).

Повторный запуск `/taskloop` в том же воркспейсе продолжит прогон с **11.5**
(первая неотмеченная задача).

## 6. Рекомендации

- **Для прогона:** ничего чинить не нужно — достаточно снова выполнить `/taskloop`.
- **Для агента/ручного вмешательства:** не переписывать текст уже отправленных
  задач в tasks.md во время их выполнения без необходимости; отметку статуса
  делать без изменения самого описания, если это возможно.
- **Для развития плагина (опционально):** верификация по дословному `description`
  чувствительна к любым правкам текста шага. Если это нежелательно, стоит
  идентифицировать задачу стабильнее — например, по номеру `N.M`, который уже
  извлекается внутри description, вместо сравнения всего текста.
