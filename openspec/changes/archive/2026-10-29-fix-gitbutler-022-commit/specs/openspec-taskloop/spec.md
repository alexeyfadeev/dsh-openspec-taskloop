# Spec Delta

## ADDED Requirements

### Requirement: Проверка минимальной версии GitButler

Если `commit.tool` равен `gitbutler`, плагин перед первой задачей прогона SHALL читать `but --version` один раз за прогон и SHALL сравнивать установленную версию с минимальной `0.22.0`. При версии ниже минимальной или при нераспознанном ответе плагин SHALL останавливать прогон с сообщением о необходимости обновить GitButler, и SHALL NOT запускать задачи. Поддерживается только синтаксис команд GitButler 0.22.x.

#### Scenario: Версия актуальна

- **WHEN** `but --version` сообщает `0.22.0` или выше
- **THEN** плагин продолжает обычный порядок запуска, и сообщение о версии в ответ не попадает

#### Scenario: Версия ниже минимальной

- **WHEN** `but --version` сообщает версию ниже `0.22.0`
- **THEN** команда сообщает минимальную версию `0.22.0` и требование обновить GitButler, модели не отправляется ни одного сообщения, и файлы проекта не изменяются

#### Scenario: Версия не распознана

- **WHEN** вывод `but --version` не содержит версии вида `X.Y.Z` или команда завершилась ошибкой
- **THEN** команда останавливается с сообщением о неопределяемой версии и не начинает прогон

#### Scenario: Проверка не нужна для git

- **WHEN** инструмент коммита равен `git`
- **THEN** версия `but` не читается, и прогон не затрагивается проверкой

## MODIFIED Requirements

### Requirement: Коммит после ревью выполняется плагином

Плагин SHALL выполнять коммит после ревью сам, без участия модели, инструментом из конфигурации: `git` (все изменения рабочего дерева) или `but commit -b <ветка> -m` (GitButler; ветка выбрана по требованию «Выбор ветки GitButler для коммита»). При пустом рабочем дереве коммит SHALL пропускаться с указанием причины в докладе, а сбой коммита SHALL останавливать прогон с докладом.

#### Scenario: Коммит через git

- **WHEN** инструмент коммита равен `git` и в рабочем дереве есть изменения
- **THEN** плагин добавляет все изменения и выполняет `git commit -m` с сообщением, собранным из текста пользователя и диапазона задач

#### Scenario: Коммит через GitButler

- **WHEN** инструмент коммита равен `gitbutler`, в рабочем дереве есть изменения и ветка выбрана
- **THEN** плагин выполняет `but commit -b <ветка> -m` с тем же сообщением, а для новой ветки — сначала `but branch new <имя> -A <anchor>`

#### Scenario: Нечего коммитить

- **WHEN** рабочее дерево не содержит изменений
- **THEN** плагин не выполняет коммит и указывает в докладе, что коммитить было нечего

#### Scenario: Сбой коммита

- **WHEN** выбранный инструмент завершился ошибкой
- **THEN** плагин останавливает прогон, сообщает инструмент, код возврата и причину, и не запускает следующую задачу

### Requirement: Выбор ветки GitButler для коммита

Если `commit.tool` равен `gitbutler`, плагин перед первой задачей прогона SHALL читать applied-ветки через `but status --json` и SHALL спрашивать, в какую ветку коммитить: опцией из списка или именем новой ветки. Для нового имени SHALL спрашиваться anchor, а ветка SHALL создаваться командой `but branch new <имя> -A <anchor>` на первом непустом коммите. Выбор SHALL NOT сохраняться между прогонами. Сбой чтения веток и отмена вопроса SHALL NOT запускать прогон.

#### Scenario: Список applied-веток

- **WHEN** инструмент коммита равен `gitbutler` и в проекте несколько applied-веток
- **THEN** вопрос показывает их имена, и коммит группы идёт в выбранную: `but commit -b <ветка> -m`

#### Scenario: Новая ветка

- **WHEN** пользователь ввёл имя, которого нет среди applied-веток
- **THEN** плагин спрашивает anchor среди applied-веток, на первом непустом коммите выполняет `but branch new <имя> -A <anchor>`, а затем `but commit -b <имя> -m`

#### Scenario: Имя совпало с существующей веткой

- **WHEN** введённое имя совпадает с одной из applied-веток
- **THEN** оно трактуется как выбор этой ветки, и `but branch new` не выполняется

#### Scenario: Нет applied-веток

- **WHEN** applied-веток нет
- **THEN** вопрос просит только имя ветки, и ветка создаётся без anchor

#### Scenario: Пустое рабочее дерево

- **WHEN** рабочее дерево не содержит изменений
- **THEN** ветка не создаётся, а коммит пропускается с указанием причины в докладе

#### Scenario: Отмена выбора ветки

- **WHEN** пользователь отменил вопрос о ветке
- **THEN** прогон не начинается, и модели не отправляется ни одного сообщения

#### Scenario: Сбой чтения веток

- **WHEN** `but status --json` завершился ошибкой
- **THEN** прогон не начинается, а ответ команды содержит текст инструмента и подсказку о настройке

#### Scenario: Нет канала вопросов

- **WHEN** задать вопрос о ветке некому
- **THEN** плагин коммитит без аргумента ветки (`but commit -b -m`), и доклад называет это

#### Scenario: Ветка в докладе

- **WHEN** коммит выполнен
- **THEN** доклад и строка транскрипта называют ветку, в которую он попал
