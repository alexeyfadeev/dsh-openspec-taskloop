# Proposal

## Why

Прогон `/taskloop` сегодня можно только прервать насовсем. `/taskloop stop` освобождает слот прогона и не оставляет после себя состояния, а активная сессия при этом продолжает работать: команда не отменяет turn модели, поэтому «остановленный» прогон ещё некоторое время живёт в транскрипте. Из-за этого нельзя ни приостановить длинную работу, чтобы вернуться к ней позже с того же места, ни увидеть, что прогон вообще идёт: состояние видно только по ответу `/taskloop status`.

Нужны пауза с возобновлением, остановка, которая действительно останавливает сессию, и видимый индикатор прогона с диалогом управления.

## What Changes

- **Новая команда `/taskloop pause`** — прогон встаёт на паузу: turn текущей задачи отменяется через сервис сессий, цикл паркуется, слот прогона остаётся занятым, `tasks.md` не меняется.
- **Новая команда `/taskloop resume`** — припаркованный прогон продолжает работу с того же места: цикл перечитывает `tasks.md` и отправляет первую невыполненную задачу; задача, на которой прогон был припаркован, не считается провалом.
- **`/taskloop stop` останавливает и сессию**: помимо отмены цикла плагин отменяет активный turn сессии, которую ведёт прогон.
- **BREAKING (словарь и конфиг).** Существующая настройка «пауза после каждой группы задач» переименовывается в «Остановка на границе группы»: `pause.enabled` → `boundary.enabled`, исход `LOOP_END.paused` → `stoppedAtGroup`, слово `pause` отдаётся новой команде. Профиль, в котором был выставлен `pause.enabled`, после обновления читает значение по умолчанию (выключено).
- **Бейдж в шапке сессии** — виден во всех сессиях, пока прогон активен, и различает фазы «работает» и «на паузе».
- **Диалог по нажатию на бейдж** — workspace прогона, прогресс-бар по числу выполненных задач из `openspec instructions apply --json`, кнопки «пауза»/«возобновить» и «стоп», список задач с выделенной текущей.
- **HTTP-поверхность для клиента** — только loopback: чтение состояния прогона, чтение списка задач и действие (`pause` | `resume` | `stop`), которым пользуются и кнопки диалога.

## Capabilities

### New Capabilities

Нет: плагин остаётся одной capability `openspec-taskloop`, как и его страница настроек.

### Modified Capabilities

- `openspec-taskloop`: меняются грамматика команды (две новые подкоманды), требование «Один активный прогон» (пауза держит слот, `stop` гасит turn сессии), «Завершение задачи определяется по tasks.md» (разрешение переотправить задачу после возобновления) и «Остановка при неуспешном turn» (отменённый паузой turn — не провал); добавляются требования про паузу, возобновление, состояние прогона для UI, бейдж и диалог; требование про остановку на границе группы переименовывается.

## Impact

- Код: `lib/command.js` (грамматика), `lib/runs.js` (ворота паузы, текущая сессия прогона), `lib/loop.js` (точки парковки, разрешение на переотправку), `lib/control.js` (действия `pause`/`resume`, доклады), `lib/config.js` (переименование ключа), `lib/environment.js` (отмена turn сессии, чтение задач для диалога), `lib/client.js` (бейдж и диалог), `lib/index.js` (регистрация роутов).
- Новые модули: `lib/status.js` (снимок состояния прогона для UI) и `lib/routes.js` (HTTP-роуты).
- HTTP: `GET /api/openspec-taskloop/state`, `GET /api/openspec-taskloop/tasks`, `POST /api/openspec-taskloop/action`.
- Тесты: `test/command`, `test/runs`, `test/loop`, `test/control`, `test/config`, новые `test/status` и `test/routes`.
- Спека: дельта к `openspec/specs/openspec-taskloop/spec.md`.
- Совместимость: `pause.enabled` больше не читается; поведение «остановка на границе группы» остаётся прежним под новым именем.
